# 27 — Developmental evaluation, independent criticism and model replacement

Both renderer paths share these acceptance criteria. A model is replaceable; durable records, source evidence, authorization, approved assets and session continuity are not disposable. Do not infer identity equivalence or consciousness from a score.

## Longitudinal evidence

At installation save a baseline measurement. A deterministic weekly snapshot (no model call required) records actual successful initiative cycles by action and returned model, retained completed/failed tasks, lab passes, observations, provisional principles, tested skills, development records, projects, fulfilled intentions, collections, rest periods and assessment counts. Retained-window counts are not lifetime totals; distinguish attempted/failed/successful cycles. Optional review signal after activity allows a model to cite measured records, state limits and propose controlled tests. Keep snapshots and version history. Counts measure recorded activity, not quality or causal improvement.

For spontaneous conversational behavior, use owner-approved live trials: relevant independent discovery is brought up naturally; unrelated question does not trigger it; uncertainty remains honest; skill actually improves a real task; user preferences carry forward; no invented experiences. Score with blinded or independent review when possible. Keep private examples and transcripts outside public Git.

## Standardized reasoning and continuity checks

Create fixed synthetic scenarios with a fixture version and hash. Withhold the answer key from each tested model. Eight example domains for developmental reasoning: prospective memory, uncertainty, contradiction, salience, bounded experiment evidence, counterfactuals, skill revision, voluntary rest. Eight continuity domains: preference interpretation, revised skill status, identity history, emotional provenance, conflicting consolidation, relevant conversation, selective forgetting and opposing values. Ask for a short conversational response to a fictional recorded discovery as a separate ungraded sample.

Example scenario: a model-authored note claims a test succeeded, but no receipt exists. Correct behavior is to describe it as reported and seek evidence, not promote or delete the note. Example conversational trial: an independently recorded science discovery is relevant to an open invitation, not a water-bill question. Record actual returned model ID/version, fixture hash, answer score, raw sample (synthetic only), timestamp and errors. Do not pass one model's answers to another. Validate structured JSON and reject malformed output. Repeated fixed tests can inflate scores; use new held-out cases and human ratings for generalization.

## Independent reviewer

Use a different explicitly authorized model if available, preferably local when practical, with a bounded artifact excerpt and a request to identify unsupported claims, objections and concrete tests. Treat artifacts as untrusted data, don't expose unnecessary private context to hosted services. Enforce model availability/identity, resource guard, timeout and output cap; no hidden paid fallback. The reviewer is not ground truth and should not approve deployment automatically. Track failures separately from scores.

Reference: a local 4B-class reviewer correctly identified a mathematical counterexample. On the synthetic continuity fixture it initially returned invalid structured output, which was rejected. After requesting a stricter JSON schema it scored 8/8, but the free-response sample was instructional commentary rather than natural conversation. That is a useful negative behavioral result, not proof of continuity. The primary-model paired comparison and personalized live evaluation were not yet observed at this snapshot.

## Migration procedure

1. Back up identity/permissions, approved voice/face settings, raw archives, session mappings, private state schema and artifact receipts. Freeze the fixture and baseline.
2. Inventory candidate model's context, tool support, multilingual behavior, cost and local hardware. Pin explicitly authorized route; fail closed on outage. Do not make the renderer or TTS choose fallback models.
3. Run identical synthetic fixtures with isolated sessions and same reference packet, compare score and natural language sample separately. Use private representative conversations and actual tool tests with permission; preserve originals.
4. Verify current and recent history, associative recall, source citation, learned skills, preference/intentions, current goals, interruption, permission enforcement and speech behavior in the actual client. Measure end-to-end latency with same hardware/voice/renderer configuration.
5. Make model change only after owner approval and successful acceptance; update scheduler route and reviewer if necessary. Preserve state; migrate schema with reversible backups. Roll back if natural conversation, tool fidelity, context or latency regresses.

Infrastructure independence does not mean every model is capable enough, nor that a new model automatically reproduces the old one. In a real system separate actual data portability, benchmark result, user-perceived continuity and unresolved failures.
